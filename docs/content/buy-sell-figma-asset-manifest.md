## Lectura del material

El proyecto tiene contenido suficiente para construir un caso de estudio visual completo sin recurrir a interfaces inventadas:

- Producto móvil: experiencia sin sesión, experiencia autenticada, administración, moderación, estados globales y páginas institucionales.
- Flujos demostrables: descubrimiento, búsqueda, detalle, publicación, compra, conversación y gestión.
- Sistema de diseño: fundamentos, componentes, normas y documentación.
- Arquitectura atómica documentada explícitamente como **átomos**, **moléculas** y **organismos**. Esto permite hablar de un sistema atomizado como una decisión real del proyecto, no como una afirmación genérica.

## Orden recomendado para el caso

1. **Impacto de marca:** composición artística con el logotipo y uno o varios móviles limpios.
2. **Producto en contexto:** inicio, búsqueda y detalle; deben leerse como una secuencia, no como capturas aisladas.
3. **Momento humano:** conversación y confianza entre comprador y vendedor.
4. **Conversión:** checkout como culminación del flujo.
5. **Sistema que lo sostiene:** fundamentos, marca/navegación y componentes de estados.
6. **Profundidad operativa:** estadísticas de administración para revelar que el proyecto supera la capa visual.

## Criterio para las composiciones del portfolio

- Usar las exportaciones como pantalla nítida dentro de mockups blancos o negros, sin deformarlas ni regenerar su UI con IA.
- Reservar la IA para escenarios, fondos, iluminación, materiales y arte 3D; la interfaz debe seguir siendo la exportación real de Figma.
- Evitar enseñar las nueve piezas a la vez. Para la vista previa dinámica bastan tres escenas: producto, flujo y sistema.
- Mantener una duración total de 5–7 segundos y permitir que cada escena tenga tiempo suficiente para leerse.
- Conservar este directorio como fuente y generar derivados en otra carpeta cuando se construyan los mockups.
